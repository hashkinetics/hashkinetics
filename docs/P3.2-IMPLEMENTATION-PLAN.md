# P3.2 Implementation Plan — after the public testnet: what is left, in order

**Written 2026-09-03, the morning after testnet-1's first unattended rotation. Scope: everything between "a public testnet that strangers can use" and "a soak clock that is actually running, with an audit that can start from a frozen scope."** This is the leftover list from a full pass over the codebase (`chain/crates`, the circuit, the prover service), the running fleet, the wallet, the site and every document — not a wish list. Each item carries the evidence that put it here, the receipt that closes it, and a size. Tracker discipline is unchanged: this plan feeds `MASTER-BUILD-PLAN.md` §5–§7 rows; the CHANGELOG is the record; nothing is done until it ran live.

## 0 · Where we stand (measured, 2026-09-03 05:25 UTC)

**Live:** testnet-1 `hashkinetics-1-4e4ea68d`, height 15,897, four founder seats voting on v0.13.0, ~19 blocks/min since launch; protocol fee 100 micro burned from block 1 (`burned_micro = 900`); all four seats rotated themselves at heights 11,584–11,595 (04:03 UTC), zero blocks missed; `history{disk_from 1, ram_window 512}`; faucet + RPC + prover + explorer public; Windows wallet v0.13.0 pays transparent and shielded; staging-1 archived (2,932,293,982-byte tar in object storage + every host's final home); CertiK engaged; 93 in-workspace tests + 17 circuit tests; rehearsal gate GREEN 34/34 on the released binary.

**Not real yet (the honest list this plan exists to shorten):** no way to add a validator to a running chain (seats are genesis-fixed) → no external voters → **the G3 soak clock cannot start**; ~6.7 GB RSS per node (verifier client footprint); the RPC listener has no timeouts, no CORS policy, no pagination on the pool-note endpoints, unbounded bundle/gossip queues; the block log grows one file per height forever; search indexes are rebuilt from scratch on every restart; the mempool WAL is not fsynced; key material (validator seeds, wallet seeds, the faucet treasury) sits in plaintext JSON; the wallet's saves are not fsynced and a worker panic strands the UI; the state commitment is a flat hash (no light clients); commit certificates are N hash signatures (no proof-of-consensus); no fee market, no slashing; `hk-rpc` is an orphan crate and the usage banner still says v0.10; two crates ship with zero tests; nothing is audited; the site has no wallet page and documents 7 of 20 RPC methods.

**Gate map:** G3 = 30-day incident-free public soak with ≥4 external validators at ≥⅓ voting power + load benches + third-party disclosure verification → audits close (CertiK + a circuit specialist) → G4 → guarded mainnet (value caps) into the AMLR window (2027-07). Nothing in this plan is an offer of tokens; token matters follow the gates, under counsel-reviewed terms.

## 1 · The critical path (what gates the clock)

```
V1 dynamic validator set ──┐
R11 verifier memory ───────┼──→ V4 four external voters at ≥⅓ ──→ SOAK CLOCK STARTS ──→ 30 days ──→ audit scope freeze already done → audits close → G4
H1–H3 public-exposure hardening ─┘                                   (C2.8 retention + R14 alerting run alongside)
```

Everything else in this plan is either enabling (makes the path safer) or parallel (does not block it). Order of the next three sprints is in §4.

## 3 · Dependencies (what must come first)

- **V1 before V4** (obviously) and **before any promise of a seat** to an operator — until V1 ships the honest offer is "observer now, seat next".

- **H1–H3 before the soak announcement** — the announcement is an invitation to point tools at the RPC.
- **C2.8 before month two** — 1.3 M files/month is an operational cliff, not a bug.
- **A1 scope freeze after H-batch + V1**, because both change consensus-adjacent code (V1 changes consensus); anything after the freeze is a delta audit.
- **K1 before the wallet asks anyone to hold more than test units** — i.e. before any incentivized program.
