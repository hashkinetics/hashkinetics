# P6.2 — Test USDC for people who are not developers: shield, unshield, transfer from the wallets

**Scoped 2026-09-12 (Yadu: "not everyone is a dev — people should be able to shield, unshield, transfer test USDC"). Build starts 2026-09-13.** Today `USDC.sep` exists only for the CLI (`account-send … [ASSET]`, `wallet shield|pay|unshield|scan --asset`) and the bridge page; the desktop wallet (v0.14.1) and the Android wallet (v0.2.0) predate P6 and show one asset. This closes that gap without touching consensus.

## 1 · What a non-developer must be able to do (the acceptance test)

1. Open the wallet, pick **USDC.sep** from a dropdown next to the balance, and see the balance in dollars (6 decimals), not micro.
2. Press **Get test USDC** and receive a drip — no MetaMask, no Sepolia, no terminal.
3. **Send** USDC.sep to another account id (transparent), the same form as today with the asset selected.
4. **Shield** USDC.sep into its own pool, **pay shielded** to an `hkaddr:` address in USDC.sep, **unshield** back — the same three buttons as today, acting on the selected asset, and the shielded section reading "SHIELDED · USDC.sep · 2.000000 in 1 note".
5. Do all of it on Android too.
6. A stranger does 1–4 from the Windows wallet and posts the txids — that is the receipt that closes P6.2 (same standard as the bridge's B1.5 gate).

## 2 · Where the test USDC comes from — without breaking the bridge

`USDC.sep` supply − burned **must** equal the vault's Sepolia USDC (`docs/BRIDGE-GUIDE.md`, the invariant the bridge page checks in the browser). So the faucet cannot mint USDC.sep out of nothing. It doesn't need to: **the founders lock Sepolia USDC in the vault, naming the faucet's hot account, and the bridge mints the float to the faucet exactly as it did for Eddy.** Sepolia USDC is free from Circle's faucet; the vault's daily cap is 1,000 USDC; a 500 USDC float at 5 USDC per drip is 100 users. Every drip is an ordinary `USDC.sep` transfer from the faucet account; the invariant holds by construction and the receipts page can show the lock tx that funds the float.

- `faucet-serve` already accepts an asset on the drip path (`account-create DIR RPC AUTH_COMMIT MICRO [ASSET]`); add `--drip-asset 0c3c3f40…:5000000` so one faucet process serves both drips, same rate limit, `/health` reporting both floats and `drips_left` per asset.
- The wallet's **Get test USDC** calls the same web faucet endpoint with the asset id; the faucet page gets a second button.
- Refill: a founder locks more on Sepolia when `/health.low` says so (`docs/FAUCET-RUNBOOK.md` gains one section).

## 3 · `hk-wallet-core` (shared by both GUIs through UniFFI)

- `Asset { id, symbol, decimals, pool_eligible }` from `hk_getAssets`, cached with the chain id; the native asset is entry 0 with symbol from the genesis.
- `balances()` → `hk_getAccount.balances[]`, formatted with each asset's decimals.
- `send(to, amount, asset)` — the existing send with the asset appended (the tx variant already carries it since X1).
- Shielded: `shield(amount, asset)`, `unshield(amount, asset)`, `pay(hkaddr, amount, memo, asset)`, `scan(asset)`; notes stored **with their asset**; **one scan cursor per asset** (`hk_getPoolNotes {from, limit, asset}` is already per pool); `shield.json` format bumps with a migration (existing notes are the legacy asset).
- Reserve-then-sign discipline unchanged: the L-ratchet index is written before anything leaves the process, for every asset.
- Tests: per-asset note isolation, cursor independence, decimals formatting, migration of an old `shield.json`.
